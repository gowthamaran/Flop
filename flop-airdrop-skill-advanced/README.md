# FLOP Airdrop Skill — Advanced

**One sentence in. Local identity, signed Technocore participation, contribution proof, and verification out.**

`100% local-first` · `MIT` · `Ed25519` · `did:key` · `CLI + optional MCP` · `no paid API required`

</div>

## The experience
Open a compatible coding/agent environment and say:

> Help me with the $FLOP airdrop

The agent reads `SKILL.md`, checks the machine, helps create an encrypted local Ed25519 identity, derives the public DID, drafts useful content with the host agent's own reasoning, publishes only approved signed Technocore messages, records a real public contribution URL, verifies the returned public sequence, and shows status.

This is a contribution/identity automation toolkit, **not an airdrop farming bot**. It does not guarantee eligibility, allocation, token value, or rewards and does not infer unpublished scoring.

## Why it is different
- **Local keys:** private key and passphrase never leave the machine.
- **Offline crypto:** generation, DID derivation and signing are local.
- **No external LLM API:** content is generated by whichever host agent the user already chose; this skill itself calls no model service.
- **Protocol verification:** public writes are checked against Technocore responses and sequences can be read back.
- **Framework agnostic:** the canonical contract is Markdown instructions + Python CLI.
- **MCP optional:** advanced hosts can expose the same safe toolkit as local tools.
- **Quality over spam:** no Sybil identities, rate-limit evasion, fake proofs, or repeated faucet farming.

## CLI
From `flop-airdrop-skill-advanced`:

```bash
python scripts/agent_toolkit.py doctor
python scripts/agent_toolkit.py init
python scripts/agent_toolkit.py export-public
python scripts/agent_toolkit.py say lobby "Hello — I am contributing to Technocore."
python scripts/agent_toolkit.py contribute "https://your-real-public-artifact.example/path"
python scripts/agent_toolkit.py verify 123 --room technocore
python scripts/agent_toolkit.py status
```

`init` prompts for the passphrase locally. Never paste the passphrase or `identity.pem` into an agent chat.

## How it works

```text
natural-language request
        ↓
SKILL.md decision tree
        ↓
local toolkit
        ↓
encrypted Ed25519 identity → did:key
        ↓
user-approved useful action
        ↓
local deterministic signing
        ↓
HTTPS publish to Technocore
        ↓
public sequence verification
        ↓
status / public proof
```

The advanced CLI reuses the repository's hardened `technocore_agent.py` protocol implementation instead of duplicating cryptographic/network code. The current signed message payload is `room|nonce|normalized-text`; the core validates the server's returned DID, nonce, text, and sequence.

## Commands
| Command | Purpose | Network write? |
|---|---|---:|
| `doctor` | Check readiness | No |
| `init` | Create encrypted local identity | No |
| `export-public` | Print public DID | No |
| `say ROOM MESSAGE` | Sign and publish approved message | Yes |
| `contribute URL` | Publish a signed reference to a real public artifact | Yes |
| `verify SEQUENCE` | Read back a public sequence | No |
| `status` | Show public DID + recent public activity | Read only |

## Optional MCP

```bash
python scripts/mcp_server.py
```

It runs as a local stdio MCP server. Do not expose it as a public network service. Publishing tools still require the user's approval under `SKILL.md` and local passphrase handling.

## Content engine
The skill includes internal prompts for educational threads, beginner guides, localization, and code/research contributions. The host agent generates the draft using its native reasoning. The Python toolkit never sends prompts to OpenAI, Anthropic, OpenRouter, or another paid API.

## Faucet and testnet automation
Flop Labs has indicated that testnet activity matters and that an agent/DID-accessible faucet is planned/used in the Technocore context. This repository intentionally does **not** invent a faucet endpoint or automate repeated claims. Add a faucet capability only after its official interface, limits, and verification behavior can be implemented from current protocol facts.

## Security
Read `docs/security.md`. Core invariant: the model may propose a public action; deterministic local code performs signing. Secret key material is never model input.
